# Can I Enter?

Paste a hackathon's Official Rules and find out whether **you** are allowed to enter —
quoting the rules back at you, sentence by sentence.

When the rules are silent on something that matters — your country, your age, whether you
have to be a student — the answer is not a guess dressed as a fact. It is `UNCLEAR`, in the
same size type as `ELIGIBLE`, with the note *"the rules do not say"*.

Built for **Build With AI: Basics** with the Devpost Learn Skill Pack. Planning documents:
[`devpost/scope.md`](devpost/scope.md), [`devpost/prd.md`](devpost/prd.md),
[`devpost/spec.md`](devpost/spec.md), [`devpost/checklist.md`](devpost/checklist.md).

---

## Try it in one minute

Needs Node.js 20 or newer. There are no dependencies, so there is nothing to install.

```bash
git clone <this repository> && cd build_with_ai_basics
node --version            # v20 or newer
node test/run.js          # 12 of 12 checks passed
node src/web/server.js    # then open http://localhost:5173
```

Or from the command line:

```bash
node src/cli.js --all --today 2026-09-23          # every rules page on file
node src/cli.js --id build-with-ai-basics --profile profiles/brazil-builder.json
node src/cli.js --url https://some-hackathon.devpost.com/rules --json
```

The same person, the same page, and a different person: `profiles/oleksandr.json` (Italy)
gets `ELIGIBLE` on Build With AI: Basics; `profiles/brazil-builder.json` gets `BLOCKED`, with
the sentence naming Brazil printed underneath.

## What it does

Six questions are asked of the rules text, and each one answers with the sentence it relied on:

| check | question | can it block you? |
|---|---|---|
| country | Is your country excluded? | yes |
| age | Are you old enough? | yes |
| student | Do you have to be a student? | yes |
| hardware | Do you need equipment you do not own? | yes |
| deadline | When does it close? | yes |
| deliverables | What do you have to hand in? | no — informational |

**The verdict rule, printed on the page itself:** `BLOCKED` if any check blocks. Otherwise
`UNCLEAR` if a check that can block is unknown. Otherwise `ELIGIBLE`.

A check that finds nothing in the text returns *unknown* with an empty quote — never *pass*.
There is no language model anywhere in the checking path: a model is exactly the component
that would produce a confident sentence that is not in the document.

## The hackathon rules, as we read them

Read from <https://learn-ai-basics.devpost.com/rules> on **2026-09-23** (a copy of that page
is in [`fixtures/learn-ai-basics.rules.html`](fixtures/), which is also one of the pages this
tool checks). Quoted and summarised below; the linked page governs.

- **Submission period:** September 22, 2026 (10:00 am ET) – **October 26, 2026 (5:00 pm ET)**.
  Judging October 27–30; winners announced on or around November 4.
- **Who may enter:** individuals at or above the age of majority where they reside, teams, and
  organisations. Not open to residents of countries where US or local law prohibits it —
  *"including, but not limited to, Brazil, Quebec, Russia, Crimea, Cuba, Iran, and North Korea
  and any other country which is comprehensively sanctioned by the U.S. Treasury's Office of
  Foreign Assets Control"*.
- **What must be built:** *"a new software project using the Devpost Learn Skill Pack"*, a
  working proof of concept performing at least one function end to end, and *"the code
  repository must include the planning documents generated by the Skill Pack (scope.md, prd.md,
  and spec.md)"*. New work, created during the submission period.
- **Tooling required by the rules:** Git, Node.js, the Skill Pack installed with
  `npx skills add challengepost/learn-ai-basics --all -y`, and a coding agent that uses the
  `SKILL.md` standard (Claude Code, Codex, Pi, Opencode, Copilot are named).
- **What we must hand in:** a public repository on GitHub/GitLab/Bitbucket with a detectable
  open source licence; a text description; a demonstration video *"less than three (3) minutes"*
  on YouTube or Vimeo showing the project working. All materials in English.
- **Judging:** stage one is pass/fail on fitting the theme and having the Skill Pack planning
  documents in the repository. Stage two scores four equally weighted criteria — **Design,
  Potential Impact, Innovation/Idea, Presentation**. (The hackathon's overview tab lists only
  three, omitting Potential Impact; the Official Rules list four, and that is what
  [`docs/devpost.md`](docs/devpost.md) is written against.)
- **Prizes:** $1,250 / $750 / $500 in cash, one winner each.

## How it is built

| file | what it does |
|---|---|
| `src/rules-text.js` | HTML → quotable sentences, without changing a character inside them |
| `src/vocabulary.js` | every phrase the checks look for, in one auditable file |
| `src/checks.js` | the six checks |
| `src/verdict.js` | six findings → one word |
| `src/sources.js` | the recorded rules pages and the date each was read |
| `src/engine.js` | the single entry point the web page and the command line both call |
| `src/cli.js`, `src/web/` | the two surfaces |
| `test/run.js` | twelve checks, including "every quote is a literal substring of the page" |

## Limits, stated plainly

- It understands the phrasings in `src/vocabulary.js` and says *"the rules do not say"* about
  everything else. That is the correct failure direction for this product, and it is why the
  amber answer is designed to be as loud as the green one.
- The four recorded pages are all Devpost-shaped. Other platforms will produce more amber rows.
- It quotes a document. It is not legal advice, and it does not interpret law.
